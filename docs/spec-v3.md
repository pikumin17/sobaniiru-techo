# 発注書：老犬・老猫の介護記録Webアプリ（最小版）＋性格診断ページ
作成：2026-11-14（JST）　発注者：タコル　根拠：市場調査レポート（犬猫アプリ_ライバルが少ない市場調査レポート.md）

## 1. 目的
- シニアの犬猫（7歳以上の目安）を世話する家族向けに、毎日の介護記録と、家族・シッター・動物病院への申し送りを簡単にする。
- 2週間で最小版を出し、使う人の数と続く割合を見て、本格的に作るか決める。
- 集客の入口として、無料の犬猫性格診断ページを別に作る。

## 2. 背景（なぜこれか）
- 介護記録はライバルが少ない（iOS 7件・Play 4件、大手なし）。
- シニアの数：7歳以上は犬53.9%（推計367.6万頭）、猫45.2%（推計399.9万頭）。10歳以上は犬33.9%、猫29.4%（ペットフード協会 2025年調査の原本 p.39〜42：https://petfood.or.jp/pdf/data/2025/3.pdf）。
- 死別後のつらさ：死別後の後悔でいちばん多いのは「十分なケアができなかった」の56.0%（PS保険、2025年、n=400の企業調査）。北大の博士論文では、2か月後も約半数に症状あり（人数が少ないので一般化はしない）。
  - 【推測】「やれることはやった」と振り返れる記録の見せ方や、思い出アルバムは、次の版の候補になる。
- 既存アプリへの不満の上位は次の4つで、ここを最初からつぶすのが差別化になる。
  - 機種変更でデータが消える
  - アップデート後に不具合が出る
  - 有料化で過去の記録が見られなくなる
  - 家族共有がうまくいかない
- 個人開発の最大の壁は「知ってもらえないこと」なので、SNSで広がる性格診断を入口にする。

## 3. 作るもの（必須）
### A. 介護記録アプリ（Web、スマホ優先のレスポンシブ。PWA推奨）
1. **ペット登録**：名前、犬/猫、生年月日（不明可）、体重、持病メモ、かかりつけ病院メモ。複数の子を登録できる。
2. **毎日の記録**（1画面で素早く付けられること）
   - 食事量（全部・半分・少し・食べない）、水、排泄（おしっこ・うんち・状態の選択）、投薬（チェック式）、体重、睡眠や様子のメモ。
   - 記録項目は自分で追加できる（例：床ずれのケア、歩行の様子）。
   - 複数の子を一括で入力できる。
   - 今どの子を記録しているかを常に画面に大きく出す（別の子への誤記録を防ぐ）。
3. **振り返り**：日ごとの一覧と、体重・食事量の簡単なグラフ。
4. **リマインド（最小版は画面内表示だけ）**
   - 投薬や通院の予定を登録し、アプリを開いたときに「今日の予定・まだの投薬」を目立つように出す。
   - Webアプリはサーバーなしでは時刻どおりに通知を鳴らせない（Notification Triggersは開発終了、iPhoneのプッシュはホーム画面追加＋サーバーが必要）。なので、最小版では時刻通知は約束しない。
   - 画面に「時刻になっても通知は出ません。スマホのアラームと併用してください」とはっきり書く。
   - 確実に鳴る通知（プッシュ＋サーバー、またはネイティブアプリ化）は次の版で検討する。
5. **申し送り**
   - 期間を選んでPDFを作り、家族・シッター・動物病院に渡せる。
   - PDFには、記録、投薬の予定、持病メモ、緊急連絡先メモを入れる。
   - サーバーを使わずに渡せる形にする（PDFや書き出しファイルを共有）。
6. **データ保存**
   - 端末内（IndexedDB）に保存し、サーバーは使わない。`navigator.storage.persist()` を呼ぶ。
   - JSONの書き出しと読み込み（機種変更・バックアップ用）を設定画面の目立つ場所に置く。最後に書き出した日を表示し、しばらく書き出していなければ促す。
   - 過去の記録はすべて無料で見られる（有料化で隠さない）。
   - 削除の前には確認画面を出す。消した記録は一定期間、元に戻せるとなお良い。

### B. 犬猫の性格診断ページ（静的なWeb）
- 無料、登録不要、10問前後。犬用と猫用を用意する。
- 結果はタイプ名、説明文、シェア用の画像か文章（XやLINEで送れる）。
- 結果画面から介護記録アプリへ誘導する（「シニアになったらこれで記録」程度の控えめな導線）。
- 個人データは保存しない。

## 4. やってはいけないこと（必須）
- 症状から病名、薬、量を判断したり提案したりする機能（獣医師法第17条）。AI相談や獣医師チャットも入れない。
  - 記録とリマインドだけにとどめる。
  - 画面のどこかに「体調の判断は必ず獣医師へ」と表示する。
- 「心理師」「カウンセリング」などの名称や表現（公認心理師法第44条）。
- 商品へ誘導してお金をもらうのに、広告だと示さないこと（ステマ規制）。最小版では広告とアフィリエイトは入れない。
- 飼い主の住所・電話番号・位置情報を集めること。緊急連絡先は端末内のメモとしてだけ持つ。
- 診断を「病気診断」のように見せること。
- アプリ名「うちの子手帳」は既存アプリと重なるので使わない。名前は「そばにいる手帳」とする（ストアに同名なし、J-PlatPatの3通りの検索で0件、2026-11-14時点。出願するかは別途判断）。

## 5. 品質の合格条件（エメ部署のチェックリストの要点）
- 使いやすさ：主要操作（記録の追加・修正・削除、子の切り替え）が3タップ以内でできる。文字が大きく読みやすい（高齢の家族も使う想定）。エラー時に何が起きたか日本語で表示する。
- データ消失対策（すべて必須）：
  - 端末内に保存され、ブラウザを再起動しても残る。
  - `persist()` を呼ぶ。
  - JSONの書き出しと読み込みで、全データが元通りに戻る（往復テストを行う）。
  - 読み込みの前に、上書きか追加かを確認する。
  - 削除の前に確認画面を出す。
  - アップデート時のデータ形式の変更（マイグレーション）でデータが消えない。
- 採点は「A項目がすべてYes、かつ80点以上」で合格。A項目が1つでもNoなら要修正（全45項目、A15個。必要なら全文を渡す）。

## 6. 技術の目安（任せる。変えてよい）
- フロントだけで完結する構成（例：React または Vue、Vite、IndexedDB（Dexie等）、PDFはブラウザで生成）。
- 静的ホスティングで公開できること（例：Cloudflare Pages、Vercel、GitHub Pages）。
- 月の運用費はほぼ0円を目標にする。

## 7. 納品物
1. ソースコード一式と、動かし方・公開手順（README）。
2. 公開URL（できれば）。
3. 主要画面のスクリーンショット（ホーム、ペット登録、記録、リマインド、削除確認、設定、エラー表示）。
4. データ消失対策のテスト結果（書き出し→全削除→読み込みで元に戻ることなど）。
5. できたこと、できなかったこと、次にやるべきことのメモ。

## 8. 期間
- 2週間以内（最小版）。工数が12週を超えそうなら、範囲を削って相談する。

## 9. 公開後に見る数字（2週間）
- 診断ページの利用数とシェア数、アプリの登録数、1週間後に続けて記録している割合。
- この数字を見て、本格的に作るか、やめるかを決める。
